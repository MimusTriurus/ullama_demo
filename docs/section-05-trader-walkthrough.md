# Раздел 5. Сквозной пример: живой торговец

> Черновик для статьи (часть 2). Кульминация: обе колонны — «живёт» (раздел 3) и «действует» (раздел 4) — сходятся в одном персонаже. Проследим путь одной-единственной реплики игрока от микрофона до перерисованного интерфейса.

---

## 5.1. Знакомьтесь: Торговец

Наш подопытный — **The Merchant**. Вот его описание, дословно из системного промпта (который, напомним, сгенерирован из DataAsset):

> *name: The Merchant*
> *specialization: Weapons, upgrades, medications, ammo*
> *traits: Charismatic, loves making deals, always smiling.*

Он умеет ровно шесть вещей (это его грамматика из раздела 4):

| Действие | Когда |
|---|---|
| `SellItem` | продать товар игроку |
| `ShowItem` | показать конкретный товар |
| `ShowItemsByCategory` | показать категорию (оружие, патроны, медикаменты…) |
| `OutOfStock` | товара нет в наличии |
| `NotEnoughGoldToBuy` | у игрока не хватает денег |
| `DoNothing` | вопрос не по адресу |

Ассортимент — от `pistol` и `shotgun` до `medkit` и `rocket_launcher`. А теперь — за дело.

## 5.2. Жизнь одной реплики

Игрок — потрёпанный, с почти пустым кошельком — подходит к прилавку и говорит вслух:

> 🎙️ «Дай-ка мне вон тот дробовик»

Что происходит дальше по шагам:

```
 ┌─ 1. STT (Qwen) ──────────────────────────────────────────────────┐
 │  голос ──▶ текст: "Дай-ка мне вон тот дробовик"                    │
 └───────────────────────────────────┬───────────────────────────────┘
                                      ▼
 ┌─ 2. Понять тему (эмбеддинги) ─────────────────────────────────────┐
 │  вектор фразы ≈ ближайшая запись базы: "SellItem | item: shotgun" │
 │  → тема: продажа дробовика → какой DataGetter звать                │
 └───────────────────────────────────┬───────────────────────────────┘
                                      ▼
 ┌─ 3. Собрать контекст (DataGetter) ────────────────────────────────┐
 │  GetNpcState:  "shotgun — цена 300, на складе: 5 шт"               │
 │  GetUserState: "игрок ранен, золота 250"                           │
 └───────────────────────────────────┬───────────────────────────────┘
                                      ▼
 ┌─ 4. Запрос к модели ──────────────────────────────────────────────┐
 │  system prompt (роль + правила) + контекст + фраза игрока          │
 │  { "request_of_user": "...", "state_of_user": "...",              │
 │    "state_of_npc": "..." }                                         │
 └───────────────────────────────────┬───────────────────────────────┘
                                      ▼
 ┌─ 5. Генерация под грамматикой (llama.cpp, локально/GPU) ───────────┐
 │  GBNF разрешает только валидный JSON и действие из списка          │
 │  модель видит: денег 250 < 300  →  выбирает NotEnoughGoldToBuy     │
 └───────────────────────────────────┬───────────────────────────────┘
                                      ▼
 ┌─ 6. Структурированный ответ ──────────────────────────────────────┐
 │  { "emotion": "Sad",                                              │
 │    "answer":  "Эх, дружище, дробовик хорош, но тебе не хватает.",  │
 │    "action":  { "name": "NotEnoughGoldToBuy",                     │
 │                 "parameters": { "item": "shotgun" } } }            │
 └──────────────────┬────────────────────────────┬───────────────────┘
                    ▼ колонна «живёт»            ▼ колонна «действует»
 ┌────────────────────────────────┐  ┌──────────────────────────────────┐
 │ 7a. Голос + лицо               │  │ 7b. Действие                     │
 │  emotion=Sad → грустный сэмпл  │  │  GetActionByName("NotEnough…")   │
 │  → клонируем голос, озвучиваем │  │  → ActionHandler.Execute(VM, …)  │
 │    answer в реальном времени   │  │  → ViewModel: подсветить цену,   │
 │  → мимика + LipSync (ULSS)     │  │    показать «не хватает 50»      │
 └────────────────────────────────┘  └────────────────┬─────────────────┘
                    │                                   ▼
                    │                    ┌──────────────────────────────┐
                    │                    │ 8. UI сам перерисовался (MVVM)│
                    │                    └──────────────────────────────┘
                    ▼
        Торговец с сочувствием произносит фразу, разводя руками,
        а на прилавке подсвечивается недостающая сумма
```

Ключевой момент всей статьи — **шаг 5**. Игрок просил *продать*, ближайшая запись в базе тоже про продажу (`SellItem`). Но модель, получив от DataGetter факт «золота 250, а дробовик стоит 300», сама приняла решение и вернула **`NotEnoughGoldToBuy`**. База знаний подготовила почву, грамматика ограничила выбор допустимыми действиями, а *что именно* сделать — решила модель на основе контекста. Обе колонны сработали как одна система.

## 5.3. Одна фраза — разные исходы

Самое наглядное доказательство, что перед нами не скрипт с ветвлениями, а живая реакция на контекст: **та же реплика** «дай дробовик» приводит к разным действиям в зависимости от состояния мира и игрока.

```
   «Дай-ка мне дробовик»
            │
            ▼         что принёс DataGetter          →  что решила модель
   ┌────────────────────────────────────────┐     ┌──────────────────────┐
   │ денег хватает, товар есть               │ ──▶ │ SellItem (Happy)      │
   │ денег мало                              │ ──▶ │ NotEnoughGoldToBuy(Sad)│
   │ товара нет на складе                    │ ──▶ │ OutOfStock (Sad)      │
   │ «а расскажи про политику в столице»     │ ──▶ │ DoNothing (Neutral)   │
   └────────────────────────────────────────┘     └──────────────────────┘
```

Ни одну из этих веток мы не программировали в Blueprint вручную как «если–то». Мы лишь:

1. описали торговца и его действия в **DataAsset** (из этого сгенерировались грамматика и промпт);
2. написали **DataGetter'ы**, которые приносят факты;
3. реализовали **ActionHandler'ы** — что физически делает каждое действие.

Всё остальное — понимание, выбор, эмоция — берёт на себя связка «RAG + модель + грамматика».

## 5.4. Почему это ощущается живым

Соберём вместе, что именно создаёт эффект «настоящего собеседника», и к каким разделам это отсылает:

- **Реагирует на тебя лично** — раненому посочувствует, богатому улыбнётся (эмоция от `state_of_user`, раздел 3.2).
- **Знает свой мир** — не выдумывает цены и наличие, берёт их из DataGetter (раздел 3.1).
- **Действительно что-то делает** — меняет инвентарь и интерфейс, а не просто говорит (раздел 4).
- **Отвечает голосом и почти сразу** — клонированный голос под эмоцию + потоковая озвучка по предложениям (раздел 3.2).
- **Не ломается** — грамматика не даёт выдать мусор или несуществующее действие (раздел 4).

И всё это — **локально**, без единого обращения в облако.
