# Раздел 3. Эмоции NPC: Expressive Agent

> Черновик для статьи (часть 2). Проблему (плоский NPC) и подход обозначили в разделе 1. Здесь — как эмоция выводится из ситуации и как она оживляет персонажа. Действия — в разделе 4.

---

## Идея

Идея простая:

> Вместе с текстовым ответом модель возвращает **тэг эмоции**, выведенный из всей ситуации. Этот тэг задаёт мимику MetaHuman и выбор голосового сэмпла для клонирования при синтезе речи.

Без этого NPC отвечает одинаково-ровно: одна интонация и одно выражение лица на любую реплику — благодарность или хамство. Такой собеседник ощущается автоответчиком, а не персонажем. Значит, нужна не «эмоция вообще», а **эмоция как реакция на конкретного игрока здесь и сейчас**.

---

## Откуда берётся эмоция

Эмоция — не случайный декор и не отдельный запрос к модели, а **вывод из ситуации**. Модель выводит тэг из того же контекста, что уже собран для ответа по сути (раздел 2): тон запроса игрока + состояние игрока + состояние NPC.

```
   ВХОДЫ (тот же контекст, что и для ответа)          ВЫХОД
   ┌─────────────────────────────────────┐
   │ тон и суть запроса игрока            │
   │   «дай живо!» / «спасибо, выручил»   │──┐
   ├─────────────────────────────────────┤  │
   │ состояние игрока   (раздел 2)        │  │     ┌──────────┐
   │   «ранен, денег в обрез»             │──┼───▶ │  модель  │──▶ тэг эмоции
   ├─────────────────────────────────────┤  │     └──────────┘        │
   │ состояние NPC      (раздел 2)        │  │                        ▼
   │   «редкий товар, давно не брали»     │──┘              Neutral/Happy/Sad/
   └─────────────────────────────────────┘                 Angry/Surprise
```

Поэтому это **не таблица «фраза → лицо»**, а вывод из всей ситуации сразу. Игрок хамит (`тон`), но принёс редкий трофей (`состояние NPC`) да ещё и ранен (`состояние игрока`) — модель взвешивает всё вместе и может выдать `Surprise` вместо ожидаемого `Angry`. Один и тот же вопрос в разном состоянии даёт разную реакцию.

И тэг приходит **вместе с ответом** — одним структурированным объектом, а не отдельным вызовом:

```json
{
  "emotion": "Happy",
  "answer":  "Конечно, вот лучшие стволы в городе!",
  "action":  { "name": "ShowItemsByCategory", "parameters": { "category": "weapons" } }
}
```

- **`emotion`** — тэг, одна из пяти эмоций (`Neutral`, `Happy`, `Sad`, `Angry`, `Surprise`).
- **`answer`** — текст, который уйдёт в озвучку.
- **`action`** — то, что изменит игру (об этом — раздел 4).

Что гарантирует, что тэг всегда из этих пяти, а объект — валидный, разберём в разделе 4 (там же — про действие).

---

## Тэг эмоции → голос и лицо

Дальше тэг расходится по двум каналам и «оживляет» MetaHuman:

```
                            тэг: "Happy"
                                │
              ┌─────────────────┴─────────────────┐
              ▼                                     ▼
   ┌──────────────────────────┐        ┌──────────────────────────┐
   │  сэмпл голоса под эмоцию  │        │   мимика MetaHuman        │
   │  (референс для клонир.)   │        │   выражение лица          │
   │  Neutral/Happy/Sad/       │        │                           │
   │  Angry/Surprise           │        └──────────────────────────┘
   └──────────┬───────────────┘
              ▼
   ┌──────────────────────────┐
   │  синтез речи (клонирование│  ← текст `answer` озвучивается
   │  голоса) в реальном времени│     голосом NPC с нужной эмоцией
   └──────────┬───────────────┘
              ▼
   ┌──────────────────────┐
   │  LipSync (ULSS)      │  ← синхронизация губ по синтезированному аудио
   └──────────────────────┘
```

Ключевой момент: голос **не проигрывается из заготовок**. В DataAsset персонажа лежат **сэмплы его голоса с разными эмоциями** — но это не готовые реплики, а **референсы для клонирования**. Пришёл тэг `Happy` — берём радостный сэмпл как образец тембра и настроения и **в реальном времени синтезируем этим голосом сам текст ответа** (voice cloning). Так NPC произносит любую сгенерированную фразу — своим узнаваемым голосом и с нужной эмоцией, — а не ограничен набором записанных заранее строк. Параллельно тэг включает мимику, а липсинк подгоняет губы под получившееся аудио.

---

## Итог раздела

Характер NPC складывается из двух вещей:

1. **Эмоция — реакция на ситуацию**, а не случайный фон: модель выводит тэг из тона запроса и состояния игрока/NPC (тот же контекст из раздела 2) и отдаёт его в структурированном ответе.
2. **Голос клонируется в реальном времени** из эмоциональных сэмплов NPC, а тэг заодно управляет мимикой и липсинком.

Теперь NPC помнит (раздел 2) и проявляет характер (раздел 3) — то есть красиво *реагирует*. Но чтобы он ещё и *менял игру*, нужен надёжный механизм действий — к нему и переходим.

## Заметки автора (не для публикации)

- Терминология: «**тэг эмоции**» — согласовано с 1.2 (Expressive Agent). Оперируем абстракциями; имена типов — ниже.
- Входы эмоции: три (тон запроса + состояние игрока + состояние NPC) — согласовано с обновлённым 1.2 (там тоже теперь три). Держит пример «хамит, но принёс трофей».
- JSON-пример: действие `ShowItemsByCategory` / `category: weapons` — реальное из грамматики торговца (раздел 4). Раньше стояло выдуманное `show_items` / `оружие` — исправлено.
- Voice cloning: в `UNPCDataAsset.NpcVoices` (`FNpcVoices`) лежат сэмплы-референсы по эмоциям; речь синтезируется в реальном времени по тексту `answer` (не проигрывание заготовок).
- Эмоции: `ENpcEmotion { Neutral, Angry, Happy, Sad, Surprise, None }` (в тексте — пять «рабочих», `None` не показываю).
- Структура ответа: `FLlmResponseData { Emotion, Answer, Action{Name,Parameters}, Thoughts }` (парсинг — `ResponseFromJsonString`). Поле `Thoughts` в статье не показываю.
- Факт-чек: реально ли тэг эмоции управляет мимикой MetaHuman (в схеме утверждается «мимика») — подтвердить в BP-графе.
- Факт-чек: используется ли `Thoughts` в проде или только для отладки.
