# Раздел 1. С высоты птичьего полёта

> Черновик для статьи (часть 2). Задача раздела — дать читателю карту целиком, чтобы дальше можно было нырять в детали, не теряя контекст.

---

## 1.1. Что не так было с PoC

В первой части мы собрали работающий прототип: персонаж слышал игрока, отправлял распознанный текст в языковую модель, получал ответ и озвучивал его с движением губ. Это впечатляло на демо — ровно тридцать секунд, пока не начинаешь задавать вопросы:

- NPC **не помнил фактов мира** — он придумывал цены, имена и события на ходу.
- NPC **ничего не делал** — только говорил. Нельзя было попросить «покажи топоры» и увидеть реакцию игры.
- Персонаж был **эмоционально плоским** — один голос, одно выражение лица на любую реплику.
- Всё было **захардкожено** под одного героя — добавить второго значило переписать половину проекта.

Иными словами, у нас была *говорящая голова*. Во второй части мы превращаем её в **участника игры**: того, кто помнит, чувствует и действует.

---

## 1.2. Что мы с этим сделали

На каждую боль — свой ответ. Всё это и есть содержание статьи:

| Боль из 1.1 | Решение | Где в статье |
|---|---|---|
| не помнил фактов мира | **RAG**: контекст под запрос подтягивает DataGetter | раздел 2 |
| был эмоционально плоским | **эмоция в ответе** → голос (клонирование) и мимика | раздел 3 |
| ничего не делал | **function calling**: GBNF-грамматика + ActionHandler → MVVM | раздел 4 |
| был захардкожен | **data-driven NPC**: персонаж описан данными, артефакты генерируются | раздел 1.3 |

Память (раздел 2) и эмоции (раздел 3) — это **«NPC, который живёт»**; function calling (раздел 4) — **«NPC, который действует»**. Всё вместе сходится в торговце (раздел 5), а как это устроено и масштабируется — тут же, в 1.3.

---

## 1.3. Полный конвейер — и что в нём меняется под NPC

Прежде чем разбирать по частям — вот весь путь одной реплики игрока, от микрофона до реакции игры. Заодно пометим, что в этой трубе **общее для всех NPC** (◇ каркас), а что **своё у каждого** (● из его DataAsset):

```
 ◇ каркас — один на всех NPC        ● сменное — из DataAsset этого NPC

 ┌──────────────┐   голос     ┌───────────────┐   текст запроса
 │    Игрок     │ ──────────▶ │ ◇ STT (Qwen)  │ ─────────────┐
 │  (микрофон)  │             │  речь → текст  │              │
 └──────────────┘             └───────────────┘              ▼
 ┌───────────────┐                  ┌────────────────────────────────────┐
 │ ◇ База знаний │  релевантные     │ ◇ ULlamaPlugin (llama.cpp)          │
 │   (RAG-движок)│ ─── факты ─────▶ │   локальный инференс, CUDA          │
 │ ● факты NPC   │                  │ ● модель + LoRA + промпт + грамматика│
 └───────────────┘                  └──────┬────────────────────┬────────┘
                                           │ текст ответа        │ эмоция + действие
                                           ▼                     ▼
                          ┌──────────────────────┐  ┌───────────────────────────┐
                          │ ◇ TTS — синтез речи  │  │  Эмоции + ActionHandler    │
                          │ ● сэмплы голоса NPC   │  │ ● ActionHandler (Blueprint)│
                          └──────────┬───────────┘  └────────┬──────────────────┘
                                     │ аудио                  │
                        ┌────────────┘                        ▼
                        ▼                            ┌───────────────────────────┐
              ┌──────────────────┐                   │ ◇ MVVM UI                  │
              │ ◇ ULSS / LipSync │                   │  инвентарь торговца и т.д.  │
              │  анимация губ MH │                   └───────────────────────────┘
              └──────────────────┘
                        │
                        ▼
        MetaHuman говорит — губы, мимика и эмоция синхронно
```

> **TODO для вёрстки:** перерисовать в вектор (это ASCII-черновик). Каркас (◇) и сменную часть (●) развести цветом; при желании дополнительно подсветить колонны «живёт» (RAG + эмоции) и «действует» (действие + UI).

Видно главное: **движки — общие** (◇). STT, инференс, синтез речи, LipSync, UI одинаковы для любого персонажа и переиспользуются даже в другом проекте; базовая модель к тому же грузится в память один раз на всех — десять торговцев делят одну, а не тянут десять копий. А всё, что делает торговца именно торговцем, — **сменное** (●) и берётся из его `DataAsset`: факты, модель с LoRA, промпт с грамматикой, сэмплы голоса и логика действий (ActionHandler / DataGetter в Blueprint).

Отсюда ответ на главный вопрос роста: добавить нового NPC — это заполнить DataAsset и дописать его обработчики, а не переписывать движок. **Персонаж становится контентом, а не кодом.** Детали блоков — в разделах 2 (память), 3 (эмоции) и 4 (действия), а автосборка промпта, грамматики, базы и LoRA из DataAsset — тема части 3.

И ещё одно, общее для всей схемы: весь путь проходит **локально**, без облака и интернета — приватность, никакой сетевой задержки и платы за токены (и свои грабли, о них в разделе 6).

## Заметки автора (не для публикации)

- STT: считаем, что распознавание реализовано на **Qwen-STT** (в части 1 был Vosk). В коде проекта самого STT-модуля нет — при необходимости описать его как внешний/отдельный компонент.
- Схему 1.3 обязательно перерисовать в вектор; ASCII — только чтобы согласовать состав, потоки и разметку каркас (◇) / сменное (●).
- Таблица 1.2 (боль → решение → раздел) намеренно = оглавление статьи. Если меняем структуру — синхронизировать.
- Архитектура (каркас + сменная часть) НЕ выделена в отдельный подпункт: по решению автора нанесена прямо на схему 1.3 значками ◇/●, отдельная схема «слои» и «второй NPC» убраны за ненадобностью. Пришла сюда из бывшего раздела 6. Детали — в разделах 2–4. Имена API (`UNPCDataAsset`, `UNPCDataRegistry`, `UULlamaActionHandlerBase`, `UKnowledgeBaseDataGetterBase`) в тексте не приводим — при желании добавить сноской.
- Разметка ◇/● на схеме: движки — каркас; данные и BP-логика конкретного NPC — сменное. ULlamaPlugin помечен и как ◇ (движок общий), и внутри как ● (модель/LoRA/промпт/грамматика — из DataAsset); если при вёрстке двойная метка мешает — оставить движок ◇, а сменное показать входящей стрелкой от DataAsset.
- Разделяемая модель с подсчётом ссылок — `FULlamaModelRegistry` в `ULlamaManager.cpp` (Acquire/Release, ключ `ModelFilePath|Lora|GpuLayers|NCtx`). Подана мельком.
- Факт-чек: реально ли в проекте сейчас больше одного NPC, или второй — гипотетический. Формулировка «сменная часть под каждого NPC» работает в обоих случаях.
