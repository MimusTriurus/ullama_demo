# Статья, часть 2 — рабочий план

**Тема:** от «говорящей головы» (PoC из части 1) к живому и полезному NPC.
**Часть 1:** https://habr.com/ru/articles/807561/ (PoC: UE 5.3, Vosk + Mistral 7B + Piper + Oculus LipSync + MetaHuman).

## Параметры (согласовано)

- **Гвоздь двойной:** NPC, который *действует* (function calling) + NPC, который *живёт* (RAG + эмоции).
- **Формат:** мало кода, много схем. Единственный уместный листинг — формат действий / GBNF.
- **Аудитория:** смешанная (как ч.1) — бережно объясняем термины и со стороны LLM, и со стороны UE.
- **Сквозной пример:** один — NPC-торговец.

## Сквозная идея

> В части 1 персонаж научился *говорить*. В части 2 он научился **помнить, чувствовать и действовать** — перестал быть «говорящей головой» и стал участником игры.

Две несущие колонны:
- **Живой** → RAG (память фактов) + эмоции (голос / мимика).
- **Полезный** → function calling (влияет на игровой мир).

## Арка трилогии (важно держать в голове)

Финал ч.2 (раздел «грабли») готовит почву для ч.3:

> Маленькие модели ошибаются и плохо тянут длинную историю чата → в части 3 автоматически дообучаем **LoRA-адаптер под конкретного NPC**, опираясь на его описание в DataAsset.

Крючки, которые уже есть в коде и их стоит «подсветить» заранее:
- `FULlamaInferenceConfig.LoraAdapterFilePath` — слот под адаптер уже заложен.
- Data-driven описание NPC (`UNPCDataAsset`) — будущий источник обучающей выборки.

- «Говорящая голова» → участник игры: что даёт часть 2 (помнит/чувствует/действует), без дублирования 4 болей (это 1.1).
- Арка трилогии: потолок мелкой модели → часть 3 (автодообучение LoRA). Крючок-гифка с торговцем.

### 1. С высоты птичьего полёта — `section-01-overview.md`
- 1.1 Проблемы PoC (4 боли).
- 1.2 Наши решения: таблица «боль → решение → раздел» (= оглавление).
- 1.3 Схема полного пайплайна (STT → RAG → LLM → эмоция/действие → TTS/LipSync/MVVM) с разметкой ◇ каркас / ● сменное (из DataAsset). Архитектура и масштабируемость нанесены прямо на эту схему — отдельного подпункта и второй схемы нет. Перенесено и сжато из бывшего раздела «архитектура»; детали — в разделах 2–4.

### 2. Память NPC — `section-02-memory.md`
- Проблема «золотой рыбки» (ирония: дедушка с Альцгеймером).
- База знаний = набор триггеров; эмбеддинги (врезка для новичков) → тема запроса.
- Триггер → DataGetter → контекст (GetNpcState/GetUserState). Универсальность источника.
- Роль базы: контекст, НЕ выбор действия (пример OutOfStock/NotEnoughGoldToBuy).

### 3. Эмоции NPC — `section-03-emotions.md`
- Эмоция = реакция на игрока (через `state_of_user`).
- Структурированный ответ (emotion/answer/action).
- Эмоция → клонирование голоса + мимика + LipSync (voice cloning из сэмплов).

### 4. NPC, который действует — `section-04-function-calling.md` *(гвоздь)*
- 4.1 Проблема: из текста → машинная команда; действие только из JSON.
- 4.2 GBNF-грамматика (реальная, из `inference_cfg.json`) + генерация из DataAsset. Единственный листинг.
- 4.3 ActionHandler → MVVM (меняем данные, не пиксели).

### 5. Сквозной пример — торговец — `section-05-trader-walkthrough.md` *(кульминация)*
- Видео-центричный: минимум схем, доказательство в роликах.
- 5.1 Знакомство + скриншот DataAsset; 5.2 базовый диалог; 5.3 разные исходы (OutOfStock/NotEnoughGold); 5.4 вопрос не по адресу (DoNothing); 5.5 попытка обмана (модель не проведёшь); 5.6 итог.

### 6. Грабли + мост в часть 3 — `section-06-pitfalls-and-part3.md`
- 6.1 Главная боль: без LoRA точность низкая (грамматика чинит форму, не смысл).
- 6.2 Ответ: автоматизированный MLOps-пайплайн (датасет из DataAsset → LoRA → оценка → версионирование) + эмбеддинги. Тизер части 3.
